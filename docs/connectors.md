# Account connections and imported context

Gravity has account-owner connection flows for Gmail, Google Calendar, LinkedIn through Unipile V2, and Fireflies. Adapter and isolation tests use fictional provider responses. A configured adapter is not proof that a real account has completed consent or synchronized successfully; record live qualification separately.

## Setup

Set a persistent `INTEGRATION_ENCRYPTION_KEY` containing 64 hexadecimal characters, and a random `CRON_SECRET` with at least 32 characters. Credentials use AES-256-GCM with organization, owner and connection identity authenticated as associated data. Keep these keys in server environments and recovery storage, never browser variables. Changing the encryption key without migrating stored credentials requires reconnecting accounts.

Run the reviewed database migrations. Migration 0007 adds connection checkpoints and the server-only `integration_flows`, `integration_items` and `integration_receipts` tables. Each has RLS, the trusted server policy, runtime CRUD grants and revocations for public/Supabase browser roles. Domain services still enforce organization/product/account ownership; RLS is not a per-human session policy.

The Vercel configuration schedules `/api/integrations/cron` every five minutes. Vercel sends `Authorization: Bearer <CRON_SECRET>`. This frequency requires a compatible existing plan; a Hobby installation must remove/change the schedule or use its own authenticated scheduler. Do not silently upgrade a plan. The worker processes four durable receipts and at most four connected accounts per run, two accounts concurrently, with persisted cursors and leases. Larger installations need a dedicated worker and fair scheduling sized to measured throughput. It logs only aggregate counts and duration under `gravity.integrations.cron`.

## Gmail and Google Calendar

Google sign-in authenticates the CRM identity. Mailbox/calendar access has separate consent, random one-time expiring state bound to the initiating user/product, and S256 PKCE. Configure the authorized callback `<APP_URL>/api/integrations/callback/google` in the Google client while retaining the sign-in callback. Enable the Gmail and Calendar APIs. `GOOGLE_INTEGRATION_CLIENT_ID` and `GOOGLE_INTEGRATION_CLIENT_SECRET` optionally select a dedicated integration client; otherwise the login client's server credentials are used.

Permissions are `openid email` plus `gmail.readonly` or `calendar.events.readonly`. No send or calendar-write scopes are requested. Google verification requirements and audience/testing restrictions must be qualified for your deployment, especially restricted Gmail scopes. Gravity does not remove Google's unverified-app warning or turn an unverified installation into a publicly verified application. [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth).

Gmail starts with the past 30 days, 20 message references per page and at most five concurrent hydrations. It persists the initial history baseline, then uses incremental message-added history. Expired history (404) resets bounded backfill; other failures retain the checkpoint. Calendar reads the primary calendar, starts 30 days back, paginates events and preserves the final sync token. Expired tokens (410) trigger full resync; changed and canceled linked events update the same meeting. All-day events currently use midnight UTC. Secondary calendars, attachment downloads and Gmail watch/Pub/Sub are not implemented. [Gmail sync](https://developers.google.com/workspace/gmail/api/guides/sync), [Calendar sync](https://developers.google.com/workspace/calendar/api/guides/sync).

Updates arrive through scheduled polling, not instant Google push. Backfill messages older than the first account connection add context without creating fresh reply tasks, blocking approvals or pausing current outreach. Later incoming messages on explicitly linked conversations create reply tasks and invalidate stale approvals. Outbound observations reconcile pending replies against the latest conversation message. Reading or observing a sent message never dispatches one.

## LinkedIn through Unipile V2

Ordinary LinkedIn OAuth does not provide this inbox connection. Each user connects their account on Unipile's hosted authentication page; Gravity does not collect the LinkedIn password. In **Connections → Set up Unipile**, each user verifies their own V2 API key, copies their unique webhook URL, creates that signed endpoint in Unipile, then saves its signing secret. Use a scoped Account API key when available. The fixed API origin prevents credential forwarding to arbitrary hosts. [Unipile scopes](https://developer.unipile.com/v2.0/docs/scopes).

Migration 0008 adds encrypted, owner-private `provider_configurations` with RLS and server-only grants. Settings belong to one user in one organization. Public responses expose only setup ID, webhook URL and readiness; they never return credentials. `UNIPILE_API_KEY` and `UNIPILE_WEBHOOK_SECRET` are no longer read, so hosted users cannot inherit an operator's provider subscription. Only the server encryption key and scheduler credentials remain deployment settings.

The webhook's `configurationId` routes a delivery; its matching HMAC authenticates it. Pending hosted-auth state also binds the configuration version, organization and owner. Provider account identifiers are namespaced by setup, preventing collisions between separate Unipile applications. Removing a setup deletes saved keys, disconnects its accounts, cancels pending flows and invalidates stale workers while preserving imported CRM history. To replace credentials after connecting an account, explicitly remove the setup and create a new one. Removing in Gravity does not delete the provider's application/account or cancel its billing.

Subscribe to `account.add`, `account.reconnect`, `account.status.running`, `account.status.disconnected`, `account.status.errored`, `account.remove` and `message.new`. The hosted request includes expiring `state`, and the signed account payload must return that state. Only that authenticated callback binds the provider account. An arbitrary `account_id` in a browser redirect cannot claim a LinkedIn account. Duplicate account callbacks are idempotent and cannot restore a disconnected account. [Hosted authentication](https://developer.unipile.com/v2.0/docs/authenticate-with-hosted-auth).

Signatures use `unipile-signature: t=seconds,v0=hex`, HMAC-SHA256 over the timestamp, dot and exact raw body. Verification uses constant-time comparison and a five-minute timestamp window. Accepted new message events are durably deduplicated before acknowledgement; processing and provider reads happen outside ingress. History uses chat/message cursors, and message identity includes both chat and message ID because V2 IDs are only unique within a chat. [Webhook configuration](https://developer.unipile.com/v2.0/docs/configure-a-webhook), [V2 messaging migration](https://developer.unipile.com/v2.0/docs/migration-messaging-api).

Check existing entitlements before purchase. At the research date, Unipile lists €49/$55 per month for up to ten accounts, excluding VAT, with a seven-day trial. This is a provider charge separate from hosting, and its LinkedIn connection must be qualified for your account and intended use. No subscription is purchased by configuring the adapter. [Current pricing](https://www.unipile.com/pricing-api/).

## Fireflies

In Connections, paste the account owner's API key. Gravity verifies the API owner and imports only transcripts owned by that account. The UI returns a per-connection V2 webhook URL and signing secret once; add them in Fireflies webhook settings for `meeting.transcribed` and `meeting.summarized`. Store the secret before closing the dialog. Reconnect can recover webhook setup for the authorized owner. Do not use a shared team key to imply consent from every teammate.

`X-Hub-Signature: sha256=hex` authenticates the exact body. Ingress stores a deduplicated meeting reference, and the background worker retrieves the authoritative transcript/summary and rechecks its owner. The account history poll provides recovery when a webhook is missed. Summaries and proposed actions become reviewable notes, not accepted promises or sent outreach. API access/webhooks depend on the connected Fireflies plan. [API user identity](https://docs.fireflies.ai/graphql-api/query/user), [transcripts](https://docs.fireflies.ai/graphql-api/query/transcripts), [Webhooks V2](https://docs.fireflies.ai/graphql-api/webhooks-v2).

## Ownership, review and recovery

One provider account within its configured application belongs to one organization, owner and default product. Another owner cannot claim that account. New threads/meetings enter the owner's private unmatched queue. Review loads 20 items per page with title/participant search and source filters. Counts and keyset cursors respect the current organization, product and account owner; reviewing a boundary item does not invalidate the next page. Search treats percent/underscore characters literally. Cursor ordering retains PostgreSQL timestamp microseconds and uses the item ID to resolve ties. Choose an existing person/product relationship explicitly; there is no fuzzy or automatic company matching. A conversation is linked once and remains private unless its visibility is explicitly changed through an authorized CRM workflow. Linking a meeting explicitly shares its notes with members of the selected product; the UI states that before submission.

Disconnect removes encrypted credentials, clears active leases and expires pending reconnection flows. Stale sync work checks current connection state before writes; queued deliveries are discarded for disconnected accounts. Existing imported CRM context remains. Disconnect in Gravity does not delete the underlying Unipile account or revoke every other Google's application grant; vendor-side account access can be revoked separately.

Receipts retry sanitized failures with exponential backoff up to eight attempts. Check `integration_receipts` for unresolved errors with an authorized server operator; source payloads must not be exposed in application logs. Reconciliation is idempotent. Dead-letter administration, queue metrics, retention/purge UI and dedicated high-volume workers remain follow-up work. Nothing in this release implements outbound sending, scheduling permission, opt-out enforcement or ambiguous-send reconciliation.

## MCP

`<APP_URL>/mcp` uses OAuth with organization/product consent. An assistant with verified CRM read/write consent can manage its owner’s connections, sync accounts, review/link or ignore imports, and configure personal Unipile setup through the shared API/MCP operation registry. Connection results and overview never return stored provider API keys. Google/LinkedIn connection tools return an authorization URL whose provider consent must still be completed by the account owner in the browser. Existing membership, product and private-conversation rules apply; organization-wide Unipile configuration changes require an all-products grant. `get_capabilities` reports server connector configuration separately from `accountConnectionRequired`; it does not certify a connected account. HMAC protects vendor webhooks, not MCP sign-in. See [assistant setup](setup-and-mcp.md).
