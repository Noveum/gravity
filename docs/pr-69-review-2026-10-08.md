## Confirmed findings and fixes

| Priority | Issue | Fix and regression evidence |
| --- | --- | --- |
| P1 | Yodu source creation, rotation or binding could use administrator authority captured before a lock wait. | Lock the organization before subordinate rows and refresh current authority. Demotion/removal regressions cover all three management operations; production PostgreSQL exercises concurrent transactions. |
| P1 | Internal task writes could proceed after membership or product access was revoked during a lock wait. | Stabilize organization membership and product grants before task/contact locks, then authorize again. Creation/change regressions and production PostgreSQL cover revocation. |
| P1 | LinkedIn polling with empty participants left committed history on a known thread outside the pending-history gate. | Match pending imports through the linked conversation as well as participant aliases, using the conversation's product. Sending remains blocked until history is materialized and accessible. |
| P1 | History ingestion acquired a connection before the organization, conflicting with membership/contact changes that lock the organization first. | Use organization → connection → contact/receipt ordering in imports, replies, signed receipt ingestion, processing and explicit discard. Concurrent PostgreSQL regression checks ingestion against an organization update. |
| P1 | Contact updates used product access captured before waiting for the organization lock. | Refresh membership and product authorization after acquiring the organization lock. Revocation interleavings fail with the old implementation and pass with the fix. |
| P1 | The full deal-save operation could use stale actor authority after a stage/deal lock wait, even when the selected owner remained authorized. | Lock the organization before subordinate rows and authorize the actor again. A distinct-valid-owner regression and concurrent PostgreSQL transaction cover actor revocation. |
| P2 | `update_person` replaced an existing summary with an empty string when the caller omitted it. | Make summary optional and update it only when explicitly supplied. Real HTTP and MCP regressions preserve omitted summaries, replace supplied text and allow explicit empty-string clearing. |
| P2 | Duplicate deals had no UI or MCP removal/restore operation. | Add reversible `delete_deal`/`restore_deal`, list/board confirmation, Undo and a paged archived-deal restore list. Preserve amount, currency, outcome and historical fields; exclude archived duplicates from active lists/context/forecasts and pipeline migrations. Retired or recategorized stages require an explicit compatible replacement. Isolation, version, edit-blocking, preservation, HTTP/MCP and UI regressions cover the lifecycle. |
| P2 | The new removal guard initially prevented supported edits to existing deals in archived products. | Keep the existing product-archive edit policy; reject edits only when the deal itself is archived. The unchanged baseline product suite reproduced the regression and passes after the correction. Creating records and restoring removed deals still require an active product. |
| P2 | Private message recency leaked through `checks.crossChannel` despite redacted policy timestamps. | Suppress timing-derived readiness checks whenever inaccessible or unresolved history blocks the caller. Old/recent private-history responses remain indistinguishable. |
| P2 | An action delivery claimed on one day and confirmed on another escaped the confirmation day's daily cap. | Count settled action deliveries by `sentAt`; pending/unknown claims retain their reservation behavior. A later-day confirmation regression reaches the cap. |
| P2 | A malformed signed receipt for a known thread could block sending indefinitely after retry exhaustion, with no review action. | Add paginated owner-private failed receipt summaries and explicit audited discard through existing `ignore_import`, exposed in Connections and MCP. Preserve raw evidence, enforce current ownership/grants and reject active leases. Clear related approvals; discard grants no sending permission. |
| P2 | An expired receipt worker could restore data after explicit discard or overwrite a newer claim. | Recheck lease/attempt ownership and `processedAt` under current locks before import/completion; error updates use the same comparison. Valid and malformed paused-worker regressions retain the discard. |
| P2 | Saving an action reason deleted unsaved message draft text. | Rebase only a buffer matching the submitted action version, preserving its text and stale-buffer conflict behavior. The real CRM UI edits a reason, retains the draft and successfully saves it using the new version. |
| P2 | Existing signal timestamps with microseconds became invalid when saving unrelated context. | Keep the legacy `observedAt` ISO contract and preserve unchanged values verbatim. New custom datetime fields retain their explicit millisecond contract. UI round-trip regression preserves `.123456Z`. |
| P2 | Yodu settings filters, expansion or display timezone erased a once-shown signing secret and reset a failed creation's retry ID. | Reset credentials/retry state only when organization/product changes. UI regressions retain the secret and stable retry ID through presentation changes and ambiguous failures. |
| P2 | Paging Yodu events discarded customer mappings loaded beyond the first 200. | Event pagination preserves previously loaded source/mapping pages. Expanded mapping regression covers the boundary. |
| P2 | MCP capabilities omitted the supported datetime custom field type. | Advertise the canonical field-kind list, including datetime. MCP discovery regression checks the returned capability. |
| P2 | Datetime filters could not express the second occurrence of a repeated local DST time. | Keep the workspace timezone default and expose UTC for exact datetime filter entry. UI/API regression matches the second occurrence with milliseconds and rejects a neighboring instant. |
| P2 | Database and JavaScript lowercase behavior differed for circled letters, supplementary scripts and Unicode runtime versions. | Share frozen single-character case mappings between JS and SQL `translate`; use an ASCII fast path. Label/value equality, contains and presence regressions cover circled letters, Vithkuqi and Garay alongside existing dotted-I/sigma cases. |
| P2 | Calendar construction interpreted years 0001–0099 as 1901–1999. | Construct literal calendar years and validate numeric ranges explicitly. Early-year input and recurrence regressions pass. |
| P2 | Historical timezone offsets containing seconds changed the seconds in datetime inputs and recurrence. | Include local seconds in wall-clock offsets and calendar construction. Kolkata's historical seconds offset round-trips correctly. |
| P2 | ISO year zero passed the new precise schemas but is rejected by PostgreSQL timestamps. | Reject year zero at the shared input boundary. Tests cover UTC/offset inputs and preserve year 0001 and millisecond precision. |
| P3 | Reopening an already open internal task incremented its version and recorded a false transition. | Return the unchanged task after authorization/version checks. Regression verifies stable version and no additional audit row. |
| P3 | The custom field placeholder suggested an “any field” predicate although selecting it applies no field filter. | Label it “Choose a custom field”; existing selection and filtering behavior is preserved. |
